# Monitor (#101): decisions

Date: 2026-10-11

The user widened the scope of #38: Testate watches the app process and the host over time, not
only the database, so it polls and draws graphs. The scope call is the user's. The design below was
decided by the advisor at the user's request.

## Decisions

| #   | Question | Decision | Why |
| --- | --- | --- | --- |
| Q1  | Where samples live | In `resource_readings`, one row per tick per project. Migration 0014 adds `source` (`manual` or `poll`) and lets the actor be `system` | The row shape of #38 already held one moment across a project. A second table would duplicate it |
| Q2  | How often | `limits.monitor_interval_seconds`, default 30; 0 pauses polling. The poller reads it every tick, so a change needs no restart | 30 s keeps 7 days at about 20 000 rows a project. The setting rides the existing Settings form |
| Q3  | How long | `retention.monitor_days`, default 7, for polled rows. Manual rows keep `job_history_days` | A week covers a test cycle; the daily sweep already exists |
| Q4  | CPU % and rates | Two reads of the counters about a second apart, inside one reading. Elapsed time is the kernel's tick total over the CPU count | No state kept between ticks, so a restart, an edit or a manual sample needs no special case, and SFTP latency cannot skew a rate |
| Q5  | Which processes | pm2's pid files under the login's `~/.pm2/pids`, then `/proc/<pid>/stat` and `/status` | pm2 is the stack the demo and the user run. No command runs: `pm2 jlist` would be one. A pid file path setting covers other managers later |
| Q6  | Restarts | `/proc` has no restart count. A restart shows as the app's uptime dropping | Reading pm2's own dump would be a second format to parse for one number |
| Q7  | SSH logins | The poller keeps each host's login open across ticks; closes it on an adapter edit or delete, after a read that got nothing, and at shutdown | One login a tick would put about 2 900 logins a day per host in its auth log |
| Q8  | Host keys | The poller never trusts a first-seen host key. A person's reading or browse trusts it, as before | A timer must not accept a key nobody looked at |
| Q9  | Audit and logs | A polled reading writes no audit row. One job event per tick that read something; a tick with nothing to read writes nothing | A timer is not a person's action; an instance without hosts stays quiet |
| Q10 | The series | `GET /projects/{slug}/readings/series`: min, mean and max per adapter, key and step, bucketed in SQLite with `json_each`. At most 1000 steps | The browser never loads raw rows |
| Q11 | Charts | Hand-drawn SVG, one value axis, a crosshair and one tooltip per chart, arrow keys for a keyboard. Two new tokens, `series-1` and `series-2`, validated as a pair against both themes' surfaces. The accent itself fails the palette check as a line | No chart dependency; every Solid chart library targets Solid 1 and would not run (the design-system skill) |
| Q12 | Where in the UI | The project tab Readings becomes **Monitor** (`?tab=readings` redirects). A **Monitor** menu in the sidebar lists every host and server across the caller's projects. The two-reading compare is gone | The user could not find the readings; graphs replace the compare |
| Q13 | The Monitor menu's data | One request per project for its newest reading | No new endpoint or scope logic. Marked `ponytail:` with the upgrade |
| Q14 | Demo | A clock rewrites the demo hosts' `/proc` files every second from a curve through the day, with a pm2 app that restarted three hours before the visit. The seed writes the day before the visit from the same curve | Static files draw flat lines; an empty history draws nothing |

## Out of scope

Alerts and thresholds, saved or custom dashboards, Docker container stats, Prometheus queries and
tracing. Spec 01 §1.2.18 and PRD §6 say so.
