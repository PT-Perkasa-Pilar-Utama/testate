# The journald log engine: decisions

Date: 2026-10-10. Umbrella: #37, step 4. Builds on Q2 of `2026-10-10-logs-tier.md`: `journald` reads `journalctl -o json` over SSH.

The user delegated these decisions to the advisor; they are recorded as decided at the user's request. Prefix J.

| # | Question | Decision | Why |
|---|----------|----------|-----|
| J1 | Which connection? | The SFTP connection's fields (`host`, `port`, `user`; `password` or `private_key`) and its host-key trust, through the same `ssh2` client, but an `exec` channel instead of `sftp`. Netguard and first-seen key trust are shared (05 §5.11); an agent token cannot trust a first key, as for `logfile`. | One SSH stack, one trust rule. |
| J2 | Which command may Testate run? | One template, every argument built by Testate and allow-listed, never a user's string: `journalctl -o json --no-pager --quiet -n <N> [--since=<ISO>] [--until=<ISO>] [--after-cursor=<C> \| --cursor=<C>] [-u <unit>]... [-p <level>]`. Units match `^[A-Za-z0-9:_.@-]{1,255}$` at save and do not start with `-`; times are Testate's own `toISOString()`; a cursor matches `^[A-Za-z0-9=;:+/_.-]{1,512}$`; the level comes from a fixed map. The command line is built with per-argument single quoting. No `--grep`: the text filter runs in Testate on the page. | An `exec` channel is a shell on someone's host with the adapter's credential; nothing a person types may reach it. |
| J3 | What is a source? | A named group of units, `{ name, units: [...] }`, 1–32 per adapter, names by the source-name rule. Empty `units` is the whole journal, named `all` by default. | A host runs several services; one adapter, one connection, several views. |
| J4 | Paging and follow? | journald's own `__CURSOR` is the page key, opaque to Testate and checked by its characters only. First page: the last N lines, reversed in Testate to newest first. Older: from the oldest cursor shown, backwards, the cursor line itself dropped. Follow: `--after-cursor` the newest shown, forward, capped at 10 MB. `cut_by: "lines"` when a page filled. | journald already keeps exact positions; a second cursor would only drift from it. |
| J5 | Which rights? | The SSH user in `systemd-journal`, or root. The probe runs `journalctl -n 1 -o json --quiet`; no journal answers a `no_journal` warning, a permission refusal a `journal_access` warning with `usermod -aG systemd-journal <user>`. | The common failure is the group; the fix belongs on the screen. |
| J6 | Limits and masking? | Q6's limits: 200 lines, 5 000 at most, 10 MB, a 7-day window. `__REALTIME_TIMESTAMP` (µs) is the time, `PRIORITY` 0–7 the level, `MESSAGE` the message (a byte array decoded, else `<binary>`). Fields kept: `_SYSTEMD_UNIT`, `SYSLOG_IDENTIFIER`, `_PID`, `_HOSTNAME`; every other field dropped (`_CMDLINE` can carry a secret). Built-in masks plus the source's own patterns. | journald writes 30 fields a line; the four kept say where a line came from. |

## What building it changed

- J2: times go as `--since=@<seconds>` and `--until=@<seconds>`, not ISO. `@` and whole seconds since the epoch is journalctl's absolute form, and it carries no zone to misread.
- J5: a host with no `journalctl` (exit 127, a host without systemd) answers a `no_journalctl` warning, not the `systemd-journal` group hint.
- Checked by hand against journalctl in a Debian container: paging, follow, level, window, `-u` on one and two units, both probe warnings and `no_journalctl`, and masking for a viewer.
