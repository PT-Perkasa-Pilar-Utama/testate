# A Databases menu: a tier is a menu (#63): decisions

Date: 2026-10-10

The rule comes from the Logs-tier grill (`2026-10-10-logs-tier.md`, Q3b): each tier lives in one sidebar menu that lists every adapter of that tier in scope, grouped by project, and projects stop hosting adapter lists. This issue moves databases; #37 adds Logs the same way.

| # | Question | Decision | Why |
|---|----------|----------|-----|
| Q1 | The project page after the move? | Two tabs, States and Activity. The header gains "N databases · N file stores · N log sources", each linking to its menu filtered to the project (`/databases?project=<slug>`). A project with no database shows "No databases yet" and an "Add a database" button that opens the Databases menu's dialog with the project picked. Snapshot still waits for a database. | States and activity belong to the project. The counts keep its connections one click away without a second list. The empty state keeps the first step, connect a database then take a state, where a new user starts. |
| Q2 | The starting-point rule in a cross-project menu? | Each project group shows today's banner when that project is not at its starting point, with its "Check out the starting point" button. The "New database" dialog's project picker disables such projects with the reason beside each. The API rule is unchanged. | The rule is per project, so it shows on the project's group and in the picker where the choice is made; hiding the button would block every project because of one. |
| Q3 | The Inspect page? | `/projects/inspect` keeps the eye icon, the "Built in · read-only" badge, its purpose and "Make an agent token". Its adapter list goes; counts link to each menu filtered to Inspect. In each menu the Inspect group comes first, with the badge. | One way to find any connection, and the page still says what Inspect is for and offers the agent token. The badge keeps it apart (#56 Q1). |
| Q4 | Route, API, filters, breadcrumbs? | Route `/databases`, a sidebar entry between Projects and Storage with the database icon; `?project=<slug>` filters. `GET /database-adapters`, the same shape and token scope as `GET /storage-adapters`. Filters: search, project, engine, tier, mode, status. An adapter page's breadcrumbs read Databases / project / adapter, the project crumb opening `/databases?project=<slug>`. Adapter URLs stay `/projects/<slug>/adapters/<id>`. | One endpoint per tier menu copies the working storage pair. The breadcrumb follows where the reader came from. Unchanged adapter URLs keep links, bookmarks and e2e paths working. |
