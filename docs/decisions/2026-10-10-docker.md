# The docker log engine: decisions

Date: 2026-10-10. Issue: #88. Umbrella: #37, step 5. Builds on Q2 of `2026-10-10-logs-tier.md`: `docker` reads container logs through the Engine API.

The user delegated these decisions to the advisor; they are recorded as decided at the user's request. Prefix K.

| # | Question | Decision | Why |
|---|----------|----------|-----|
| K1 | Which connection? | Two transports, as `logfile` has two. `ssh`: journald's login, host-key trust and netguard, then an OpenSSH `streamlocal` channel to the Docker socket (default `/var/run/docker.sock`, editable). `tcp`: the Engine API over HTTPS, with an optional client certificate, key and CA; plain `http` is allowed with a `plaintext` warning. Both speak HTTP through one client. | `ssh` reaches the usual host, where the socket is local only. `tcp` is the only way to reach a read-only socket proxy, the setup the guide recommends. |
| K2 | What may Testate call? | `GET` only, on five paths: `/_ping`, `/version`, `/containers/json`, `/containers/{name}/json`, `/containers/{name}/logs`. Logs always ask `follow=0`: Testate never holds a streaming call open, and the viewer's follow stays a poll (Q7). A container name matches `^[A-Za-z0-9][A-Za-z0-9_.-]{0,254}$` and is still URL-encoded into the path. | Access to the Docker API is root on the host. A fixed list of reads keeps Testate from ever being the path to anything else. |
| K3 | What is a source? | `{ name, container, format, patterns }`, 1–32 per adapter. `container` is an exact container name, which survives a recreate where an ID does not. Formats are `logfile`'s line parsers; Docker's own timestamp is the entry's time when the format has none. Each read resolves the name with `/containers/{name}/json`, which also gives `Config.Tty` and the log driver. | A compose project runs several containers on one host; one adapter, one connection, several views. |
| K4 | What level does a line get? | The format's level. A line with none is `info`, whichever stream it came from; the stream is kept as the field `stream` (`stdout` or `stderr`). | Go's `log` and Python's `logging` write to stderr by default; reading stderr as `error` would mark a whole service red. The field keeps the stream filterable. |
| K5 | Paging and follow? | By position, never by timestamp. Measured on Engine 29.5 (API 1.54), json-file driver: `tail` takes the last N lines first and `until` then filters them, so `tail=2&until=<a middle line>` answers nothing; `since` starts at the first line stamped at or after it and `until` stops at the first stamped after it, and a container's stamps can step back (line 6 stamped 42 ms before line 5). So: the first page is `tail=N`. An older page grows the tail (`tail = (k+1)·N`, doubled while short) and takes the N lines before the oldest one shown, found by its exact nanosecond timestamp and stream; a read shorter than its tail is the start of the log. Follow reads `since` the newest shown minus 5 s and keeps the lines after the newest shown one, found the same way. The user's `from`–`to` window goes to `since` and `until`, exact as long as the host's clock does not step back. Reading stops at 10 MB; the newest lines come last in Docker's stream, so `tail` is the real bound and a grown tail is sized from the first read's average line length. Without a TTY the stream is multiplexed (`[stream, 0, 0, 0, length]` frames): frames are joined per stream and split on newlines before the `timestamps=1` prefix is read. | Docker keeps no line position Testate can ask for; the line itself, by its nanosecond stamp, is the only stable mark. |
| K6 | What does the probe say? | `/_ping`, then `/version` with API 1.41 (Engine 20.10) as the floor. Warnings: `container_missing` for a source whose container does not exist, `log_driver` when its driver cannot be read back (only `json-file`, `local` and `journald` can), `docker_access` when the socket refuses the SSH user (the `docker` group, which is root on that host), `plaintext` for `http`. A TTY container gets a note, not a warning: its stdout and stderr are one stream. | The common failures are a renamed container, a driver that ships logs elsewhere, and the group; each fix belongs on the screen. |
| K7 | Limits, and what is not here? | Q6's: 200 lines, 5 000 at most, 10 MB, a 7-day window. Not here: Swarm service logs, Kubernetes, a streaming follow. Podman speaks the same API on its own socket and may work; untested. | One step, one engine. |

## What building it changed

- K6: the TTY note is a warning with the code `tty`; the probe result has no other place for a note.
- K1: the dialog has no box for a PEM block, so a client certificate is set through the API; an edit keeps it.
- Checked by hand on Colima's Docker 29.5: over TCP through a relay to the socket, four older pages past the first tail with no gap or repeat while lines arrived, follow, a TTY container, the `none` driver, a missing container; over SSH through OpenSSH with the socket mounted, a read as root, `docker_access` for a user outside the group, and a changed host key. The SSH run found that `node:http`'s request timeout needs the socket's `setTimeout`, which a channel has not; a timer replaces it.
