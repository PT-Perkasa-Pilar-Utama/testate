# The elasticsearch log engine: decisions

Date: 2026-10-10. Issue: #92. Umbrella: #37, step 7. Builds on Q2 of `2026-10-10-logs-tier.md`: `elasticsearch` reads `_search` on an index pattern, OpenSearch too.

The user delegated these decisions to the advisor; they are recorded as decided at the user's request. Prefix E.

Measured first on Elasticsearch 8.15.3: `search_after` on a time sort is strict, so the documents sharing the last time are skipped (`line 16` was followed by `line 15`, never `tie a`, `tie b`, `tie c`); a range `lte` that time returns them; a sort with `format: strict_date_optional_time_nanos` gives an RFC 3339 string with a `date_nanos` field's nanoseconds kept; a wildcard pattern matching nothing answers an empty 200, a missing concrete index 404; a missing time field, an unparseable query and a `size` above `index.max_result_window` each answer 400 with a reason.

| # | Question | Decision | Why |
|---|----------|----------|-----|
| E1 | Which connection? | `{ url, auth, user?, tls_ca?, sources }`. `url` is `http(s)`, a path prefix allowed, no login, query or fragment. `auth` is `none`, `basic` (`user` and the secret `password`), `api_key` (the secret `api_key`, sent as `Authorization: ApiKey <key>` exactly as Kibana shows the encoded key) or `bearer` (the secret `bearer_token`). `tls_ca` is a PEM CA for a self-signed cluster, set through the API as docker's is. Netguard, the pin, the kept `Host`, no redirect and the streamed 10 MB cap are Loki's, from one shared wrapper. | A self-hosted Elasticsearch 8 ships HTTPS with its own CA; without `tls_ca` only an insecure setup would connect. |
| E2 | What may Testate call? | `GET /` and `POST /{index}/_search`, with a body Testate builds. `index` is 1–8 comma-separated patterns, each `^[a-z0-9*][a-z0-9*._+-]{0,254}$` (no leading `-` or `_`, so no exclusion and no `_all`), each URL-encoded. | `_search` is a read; the path is the only place a person's text could steer it. |
| E3 | What is a source? | `{ name, index, query?, time_field, message_field, patterns }`, 1–32 per adapter. `query` is a Lucene `query_string` of at most 2 000 characters; empty matches everything. `time_field` defaults to `@timestamp`, `message_field` to `message`; both match `^[A-Za-z0-9_@][A-Za-z0-9_.@-]{0,254}$`. A document has no line format: its message is `message_field`, its level `log.level`, `level` or `severity`, and the rest of `_source` its fields. A field is read nested (`{"log":{"level":…}}`) or dotted (`"log.level"`), whichever the shipper wrote. A Kibana data view is an index pattern here. | Documents are already structured; a parser would only lose what the shipper kept. |
| E4 | Paging and follow? | Sort on `time_field` descending in the nanosecond format; no lower bound unless `from` is set, since Elasticsearch has no default window. A page asks `range lte` the mark with `size` = N + the documents already shown at the mark, and drops those, found by a 12-character hash of `_index` and `_id`. The cursor holds the mark and at most 200 such hashes; past that, or when a page makes no progress, it answers `cut_by: "lines"` with no cursor (a `ponytail:`, likelier here than on Loki: a millisecond-precision `date` field can hold hundreds of documents from one shipper batch). A short page is the end of the index. Follow asks `range gte` the newest mark ascending, a page at a time, dropping the documents shown there. Its limit: a document indexed after a poll with an earlier stamp (refresh interval, shipper lag) is missed until the viewer reloads. `track_total_hits` is off. | `search_after` loses ties; an inclusive range and the shown set do not. |
| E5 | Where do the text and level filters run? | On the page, in Testate, as for Loki. | One rule for every engine; pushing them into the query is deferred to the user. |
| E6 | What does Elasticsearch's refusal become? | A 400 that could not parse the query names its reason; a missing time field names the field; a result window names its maximum; 401 names the login; 403 the `read` privilege on the index; a 404 the concrete index; 429 says the cluster is busy (a circuit breaker) and to try fewer lines; a body past 10 MB asks for fewer lines. | Each has a fix a tester can make. |
| E7 | What does the probe check? | `GET /`: Elasticsearch 7.10 or later, or OpenSearch 1.0 or later (`version.distribution`). Then each source with `size: 1` over the last 24 hours, which is where a wrong time field surfaces as the 400. Warnings: `plaintext` for http; `no_lines` for a source that matched nothing, which also says the index pattern may match nothing. | The two silent failures are a typo in a pattern and a quiet index. |
| E8 | What is not here? | ES\|QL, EQL, KQL (Kibana's own), data views as objects, PIT and scroll, aggregations, an Elastic Cloud ID (use the deployment's Elasticsearch URL). OpenSearch speaks the same `_search` and is untested. | One step, one engine. |

## Deferred

| Branch | Reason | Who decides |
|--------|--------|-------------|
| Text and level filters as part of the query, so Elasticsearch fills a page | It rewrites the user's query; local filtering keeps it theirs but gives short pages | The user |
| Late documents in follow (a slack window, or PIT) | The shown set covers one stamp; a slack needs a wider set or server state | The user, if asked |
