# Browser-only demo: decisions

Date: 2026-10-11

Roadmap item 6: a demo a visitor opens without installing anything. Every question below was
decided by the advisor at the user's request, apart from the shape the user confirmed.

## Decisions

| #   | Question                         | Decision                                                                                                                                                                                                                                 | Why                                                                                                                                                                   |
| --- | -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Q1  | What runs behind the SPA         | The real API, in the page: the same services, handlers and routers, wired in `apps/web/demo/backend/boot.ts` the way `apps/api/src/index.ts` wires them                                                                                  | A hand-written fake of 141 routes would drift from the contract by the next change. `V1Deps` is a closed type, so a module added to the API fails the demo's type-check |
| Q2  | What stands in for Bun and Node  | Shims in `apps/web/demo/shims`, aliased only in `vite.demo.config.ts`: `bun:sqlite` over sql.js, an in-memory disk for `node:fs` and `Bun.file`, sync hashing over `@noble/hashes`, `Buffer` with `base64url`, and stubs that refuse for every driver | The API's module graph has no platform call at load time; each call on a request path got a shim, every other one a refusal that names a real server                  |
| Q3  | What the databases and servers are | The fake engine for the database, memory trees for the SFTP file store and the app host (pm2 logs and `/proc` files), behind a netguard that admits only `*.demo.internal`                                                              | Nothing in the page reaches the network: a test records every request and asserts each is a static file under `/testate/demo/`                                     |
| Q4  | State                            | Per tab, in memory. A reload starts a new demo; the banner says so                                                                                                                                                                       | No storage to clear, no state to migrate between demo versions                                                                                                        |
| Q5  | First screen                     | Seeded through the services (three accounts, the Shop project, three adapters, two states, a diff, a checkout, a reading) and signed in as admin; the banner lists every account                                                         | A visitor lands on a project with history, not an empty install                                                                                                       |
| Q6  | The session cookie               | `hono/cookie` is aliased to a jar for the tab                                                                                                                                                                                            | A page cannot put `Cookie` on a Request it builds, and a Response it builds drops `Set-Cookie`                                                                         |
| Q7  | Links                            | Clicks on in-app anchors the SPA leaves alone go through its own `navigate`; download links are fetched in the page and saved through an object URL                                                                                      | Most SPA links are plain anchors, and here a reload starts a new demo                                                                                                 |
| Q8  | Deep links on Pages              | `docs/404.html` sends any `/testate/demo/...` path to the demo with `?route=`, which the demo puts back before the SPA reads it                                                                                                          | Pages has no fallback for a single-page app; it serves the site's one 404 page                                                                                        |
| Q9  | Where it is served               | Built from source by `.github/workflows/pages.yml` on every push to main and deployed with main's `docs/`, at `https://pt-perkasa-pilar-utama.github.io/testate/demo/`. Not committed; `bun run build:demo` builds it locally into the ignored `docs/demo/`. `complete-check` does not build it. Changed after the 2.0.0 release, decided by the advisor at the user's request | A committed build put a wasm binary in main that no diff can review (Scorecard Binary-Artifacts, alert 34). The workflow serves the same `docs/install.sh`, so the check in `deploy-image.yml` still holds. The demo now follows main, not the last tag |
| Q10 | Off in the demo                  | Connecting your own servers, MongoDB, agents over MCP, the remote log engines (journald, Docker, Loki, Elasticsearch), and reading XLSX files. Each refuses with a sentence that names a real Testate                                   | Each needs a network, a driver or a native decoder the page does not have                                                                                            |
| Q11 | Dependencies                     | Dev dependencies of `apps/web`, used only by the demo build: `sql.js` 1.14.2, `@types/sql.js` 1.4.11, `buffer` 6.0.3, `@noble/hashes` 2.4.0, and `hono` at the API's exact version so both resolve to one copy                         | Nothing installed runs SQLite or sync hashing in a browser; Bun's isolated installs would not let `apps/web` resolve `hono` otherwise                                |
| Q12 | Edits under `apps/web/src`       | None                                                                                                                                                                                                                                     | The demo is the shipped SPA                                                                                                                                           |
