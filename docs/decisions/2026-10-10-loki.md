# The loki log engine: decisions

Date: 2026-10-10. Issue: #90. Umbrella: #37, step 6. Builds on Q2 of `2026-10-10-logs-tier.md`: `loki` reads with `query_range` and LogQL.

The user delegated these decisions to the advisor; they are recorded as decided at the user's request. Prefix L.

Measured first on Loki 3.4.2: `start` is inclusive and `end` exclusive; lines sharing a nanosecond split across pages in no stable order; a metric query answers `matrix`; a `limit` above `max_entries_limit_per_query` is a plain-text 400 naming both numbers; with `auth_enabled`, no tenant answers `401 no org id` and a wrong tenant an empty 200; a forward query with no `end` works and returns the line at `start`; with no `start`, Loki searches the last hour only.

| # | Question | Decision | Why |
|---|----------|----------|-----|
| L1 | Which connection? | `{ url, auth, user?, tenant?, sources }`. `url` is `http` or `https`, no userinfo, query or fragment; a path prefix is allowed (Grafana Cloud has one). `auth` is `none`, `basic` (with `user` and the secret `password`, an API token on Grafana Cloud) or `bearer` (the secret `bearer_token`), checked per `auth`. `tenant` goes in `X-Scope-OrgID`. Netguard checks the URL's host and port; `http` is pinned to the approved address, `https` keeps the host name for TLS. No custom CA. | Loki runs bare, behind a proxy, or on Grafana Cloud; those three logins cover them. |
| L2 | What may Testate call? | `GET` only: `/loki/api/v1/labels` and `/loki/api/v1/query_range`. Every call refuses a redirect: a 302 from a Loki Testate does not control would reach an address netguard never checked. Never push, delete or tail. | A query API is read-only, but a redirect is not. |
| L3 | What is a source? | `{ name, query, format, regex?, patterns }`, 1–32 per adapter. `query` is a LogQL log query: it starts with `{` and has at most 2 000 characters. The probe and every read check the answer is `streams`; a metric query (`matrix`) is refused. Testate never rewrites the query. | A log query is what a person already writes in Grafana. |
| L4 | What does a line become? | Loki's nanosecond stamp is the entry's time, always; the format gives the level, message and fields only. This differs from docker's K4 on purpose: the window, the cursor and Loki's own order all run on that stamp, and a format time that disagreed would sort one way and page another. The level is the format's, else the stream label `level`, `detected_level` or `severity`, else `info`. Stream labels become fields, `__error__` and `__error_details__` included: a failed `| json` stage is what a tester needs to see. `file` is `service_name`, else `job`, else empty. Structured metadata comes back as labels; Testate sends no encoding flags. | The stamp is the only order Loki can page by. |
| L5 | Paging and follow? | `direction=backward`, `limit=N`. `start` is `from`, else `end` minus 7 days. Testate's `to` is inclusive and Loki's `end` exclusive, so `end = to + 1 ms`. An older page asks `end` = the oldest stamp shown + 1 ns with `limit = N` + the lines already shown at that stamp, and drops those, found by their labels and text; the cursor holds the stamp and those identities. When more than that many lines share one nanosecond, a page makes no progress: it answers `cut_by: "lines"` with no cursor (a `ponytail:`). Follow reads `direction=forward` from the newest stamp shown, inclusive, with no `end`, and drops the lines already shown there. | Loki's own position is the stamp; ties are the only hole in it. |
| L6 | Where do the text and level filters run? | On the page, in Testate, as for journald and docker. A filtered page can be short; the cursor still walks on. | The user's LogQL stays theirs. Pushing the text filter into LogQL is deferred to the user. |
| L7 | Limits and probe? | Q6's: 200 lines, 5 000 at most, a 7-day window. A server with a lower `max_entries_limit_per_query` answers 400; Testate names that number. A response is read as a stream and stopped at 10 MB; a cut JSON body cannot be parsed, so it answers `ADAPTER_UNREACHABLE` naming the ceiling and saying to ask for fewer lines. The probe calls `labels` (reach and login; a 401 names the login or the tenant), then each source's query with `limit=1` over the last 24 hours. Warnings: `plaintext` for `http`; `no_lines` when a source matched nothing in 24 hours, which also says a wrong tenant looks exactly like that. | A quiet staging service can be silent for an hour, rarely for a day. |
| L8 | What is not here? | Metric queries, `/tail` streaming, a custom CA, more than one tenant per adapter. | One step, one engine. |
